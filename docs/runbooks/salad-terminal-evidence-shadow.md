# Salad training terminal evidence shadow

This is an offline, source-only safety check of sanitized, untrusted categorical
events, not a provider observer, new controller, training agent, or stop guard.

Status RUNNING, a positive replica target, EXIT_0, a passed readiness probe,
ALREADY_DONE, an existing checkpoint or final filename, and green CI do not
prove completed optimization steps, artifact integrity, independent backups,
evaluated quality or production readiness.

The pure evaluator in tools/salad/terminal_evidence_shadow.py returns
HOLD_NO_PROVIDER_ACTION for all supplied observations. It never authorizes
provider requests, dispatch, restart, stop, scale or Flagship54 shutdown.
A repeated EXIT_0 sequence with positive desired replicas is classified as
RESTART_LOOP_SUSPECTED_NOT_PROVEN rather than as a verified completed job.

Use a synthetic input with only allowlisted event tags. The CLI also rejects
raw logs and unknown identifiers, duplicate JSON properties, nonfinite data,
Boolean replica counts, oversized inputs and contradictory API/source claims.
The CLI exits 78 even if the supplied fields are syntactically coherent.

Test locally:
    python -B -m unittest discover -s tests -p test_terminal_evidence_shadow.py -v

Owner decision gate: independently confirm actual group/instance API readback,
the authorized lease/fencing epoch, pinned trainer code/image/base/dataset,
real monotonic step/heartbeat records, durable final adapter/config/tokenizer
bytes and resumable optimizer state, independent backup readback, budget, and
the correct existing operator. Do not stop or launch based on this source-only
shadow. Existing Flagship54 guard remains the only Flagship54 shutdown owner.

An authenticated Edge UI is not a substitute for repairing the approved
Salad SDK's HTTP 401 authorization failure. All publication, paid jobs,
account settings, and unrelated sources remain unchanged.
