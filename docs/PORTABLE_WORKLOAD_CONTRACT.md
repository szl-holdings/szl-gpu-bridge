# Portable workload review contract, v1

Use this opt-in sidecar to review whether one workload fits one independently observed device and whether the exact checkpoint can be read back. `tools.gpu.portable_contract.review` returns data, not a lease: `mayDispatch` and `maySpend` are always false. No component contacts a provider, discovers assets, deploys a worker or writes storage. `EXISTING_CONTRACT_VERIFIED` describes the supplied evidence at the caller's review clock, not current capacity or permission to train.

## What to retain independently

1. Keep the original JobSpec v1/v2 payload bytes (not a reserialization of the DSSE envelope), or the original Massed launch-intent bytes. Their SHA-256, kind, run ID and attempt go in the [closed sidecar schema](../schema/portable-workload.v1.json). The review does not replace signature, lease, policy, launcher or revocation checks. Other payload kinds need an explicit future version, not a permissive fallback.
2. A trusted collector or reviewer separately retains a placement-evidence digest and its preimage. Bind the exact workload, reviewed clean GitHub checkout/revision, accessible typed HF repo/revision, resource/region/SKU, target site, device-level usable memory in MiB, toolchain identity, registered cancel hook, validity interval, and versioned checkpoint storage. Populate `expectedPaths` from the pinned artifact index or an independently reviewed singleton, including required config/index files; never derive it from the shard rows under test. Supply the authenticated record's SHA-256 as `trusted_evidence_sha256`. Hashing the submitted evidence and blindly passing its own hash defeats this trust boundary.
3. Bind the retained evidence SHA-256 and immutable manifest digest in the sidecar. Budget components are integer micro-USD upper bounds for the entire single-device wall-clock interval (compute, storage, egress, contingency). The independent evidence's `costCeilings` must price compute, storage and egress for the same interval; do not substitute zero for an unknown cost. Budget line items cannot undercut those ceilings and their total including contingency cannot exceed the cap. `validThrough`, `stopBy` and `now` are Unix seconds. Independently authorize the SHA-256 of the exact sidecar bytes and supply it as `owner_contract_sha256`; it covers the cancellation owner/hook/deadline, stable logical idempotency key, price validity and cap. A digest comparison is not signature verification or evidence of who issued either pin.

The checked-in [offline tests](../tests/test_portable_contract.py) show all input shapes and call the verifier with synthetic evidence. The schema gate uses the repository's hash-locked CI `jsonschema` dependency; the streaming checkpoint reader uses only the Python standard library. The only files opened by the verifier are allowlisted schemas in this checkout.

## Checkpoint and placement rules

- **Checkpoint publication:** Write immutable shard versions first, then commit the complete manifest last. Retain its raw-byte SHA-256, version address, run ID, site, attempt, step, sizes and total bytes. No publisher or write-order monitor ships here. An incomplete publication fails verification rather than being guessed or repaired.
- **Byte readback:** Pass `(path, iterable_of_nonempty_byte_chunks)` pairs from the reviewed storage version. The verifier requires identical filename sets in inventory, manifest and readback, rejects duplicates before any dictionary conversion, then checks every byte count and digest. The storage record establishes provenance; hashing matching bytes alone does not prove where they came from. The verifier does not open supplied paths or deserialize model files.
- **Site boundary:** Choose exactly one of `hq`, `mac`, `massed`, `salad` or `hpc-slurm`. This version supports one selected device and no collectives. Extra devices in an observation never increase the chosen device's capacity. Cross-site selectors, NCCL or VRAM pooling are rejected with `INVALID_FABRIC_POOLING`. Slurm is a descriptor, not a submitted job. A Massed launch is a new allocation even if the account or lane already exists.
- **Capped proposal:** A recognized new paid request returns `PROPOSAL_REQUIRED_CAPPED`, including when the owner digest matches. A complete verified draft includes its single-unit scope, budget, controls and exact digest to review. An incomplete draft has no usable proposal. A different scope, cap or deadline changes the digest.
- **Operational boundary:** This contract does not reserve funds, persist an idempotency key, call a cancellation hook or confirm a stop. Keep existing atomic effect/reconciliation and owner admission checks operative. Offline replay neither guarantees exactly-once execution nor releases a reservation after an ambiguous stop.

## Reproduce and clean up

With the repository's CI contract dependencies installed, run `python -B -m unittest discover -s tests -p test_portable_contract.py -v` at the repository root. The example needs no credentials or network; `-B` avoids bytecode and the tests do not create temporary files, logs, stores or jobs. An optional disposable dependency environment or redirected test log belongs to its creator; remove only that scratch after review. Disabling or reverting this companion has no migration or legacy payload impact.
